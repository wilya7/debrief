# Preview Placeholder Content Catalog

**Purpose:** This file is consumed by the Debrief **Stylist** agent when generating live preview slides during the Phase 2 style dialog per REQ-STYLE-10. The Stylist renders 3 preview slides (`preview_01_title.html`, `preview_02_content_diagram.html`, `preview_03_data_exhibit.html`) using the placeholder content from the entry matching the user's `archetype` field in `debrief_state.json`. The previews let the user see how the draft style looks on representative content BEFORE approving at G2.1.

**Loaded by:** The Stylist agent, when `debrief_state.json.archetype` is set and the Stylist is about to produce draft preview slides.

**Authored by:** Carlo Fusco and Leonardo Restivo.
**Authoring date:** 2026-04-11.
**Attribution:** Original content — no upstream source, no Apache-2.0 derivation, no academic citation. All names, institutions, and findings are fictional.

## Usage rules

1. **Read the entry keyed by `archetype`.** The Stylist reads `debrief_state.json.archetype` and looks up the matching `## <archetype>` heading below (e.g., `## lab_meeting`). If no match, the Stylist falls back to the `## custom` entry.

2. **Substitute fields into the 3 preview slides:**
   - **`preview_01_title.html`** — uses `title`, `subtitle`, `author`, `institution`.
   - **`preview_02_content_diagram.html`** — uses `title` and `content_bullets` (plus a placeholder diagram generated by the Stylist as a simple Mermaid flowchart or inline SVG for the right column).
   - **`preview_03_data_exhibit.html`** — uses `title`, a placeholder chart (simple bar or line chart in inline SVG authored by the Stylist), and `data_exhibit_caption`.

3. **Do NOT mix in the user's real project content.** Even if `deck_brief.md` already exists at preview time, the Stylist MUST use placeholder content from this file, not the user's real brief. The preview is a STYLE demo, not a CONTENT preview. Mixing real content into the preview confuses the purpose of G2.1 (the user is evaluating the visual style, not the content).

4. **For `REGENERATE PREVIEWS`, vary the content.** When the user triggers `REGENERATE PREVIEWS` at G2.1 (per REQ-STYLE-10 step 7), the Stylist should vary the placeholder so the user sees a different example but in the SAME style. Variation options (see also the "Regeneration variations" section at the bottom):
   - Swap the author name from the alternate-names catalog.
   - Swap the institution from the alternate-institutions catalog.
   - Rephrase the bullets (similar meaning, different wording).
   - Swap the `data_exhibit_caption` for a sibling caption using a different chart type.

   The `archetype` entry should stay consistent across regenerations so the content density and tone remain appropriate for the user's project type.

5. **V-CON-01 compliance.** All `content_bullets` in this file are authored to comply with the `slide-qa-checklist.md` rule **V-CON-01 Textual Overload** (≤15 words per bullet). Preview slides are exempt from QA checks per Section 24.22, but the placeholder content sets the right example anyway.

6. **HTML structure comes from the draft `style_guide.md`, not this file.** The Stylist composes each preview slide's HTML following the layout grammar (REQ-STYLE-7, Section "Layout Grammar") of the current draft style guide. This file provides the CONTENT to substitute into the layout; the style guide provides the STRUCTURE (typography rules, color palette, grid, spacing, diagram-library conventions). The Stylist is an LLM and writes the HTML directly from the substituted fields — there is no bundled HTML template file and no skeleton markup in this catalog. The preview CSS is compiled from `.debrief/draft/style_config.json` via `debrief.style_compiler` per REQ-STYLE-10 step 1, and the Stylist's HTML loads that compiled CSS for rendering.

## Regeneration variations

When the user responds `REGENERATE PREVIEWS` at G2.1 (per REQ-STYLE-10 step 7), the Stylist generates new preview slides using variation on the same archetype entry. The goal is to show the user a different example in the same style — not to change the style itself.

### Alternate fictional author names

The Stylist should pick one of these names (different from the previous preview) on each regeneration:

- Example Children's Research Hospital

### Variation rules

1. **Same archetype.** The entry the Stylist selects is still keyed by `debrief_state.json.archetype`. Regeneration does NOT change the archetype.

2. **Different author+institution combination.** Pick a name and institution the user has not seen in a prior preview during this session.

3. **Same field structure.** All 6 fields (`title`, `subtitle`, `author`, `institution`, `content_bullets`, `data_exhibit_caption`) are still substituted. Regeneration does not drop fields.

4. **Rephrase bullets lightly (optional).** If the Stylist wants to show more variation, it may rephrase the `content_bullets` with similar meaning but different wording. For example, "N=32 animals, split across 4 experimental groups" → "32 subjects randomized to 4 treatment arms". The semantic content stays the same; the phrasing varies.

5. **Do not invent new archetypes.** If the user's `archetype` is `custom`, regeneration still uses the `## custom` entry. Do not fabricate a new archetype just because the user wanted variety.

6. **Preserve V-CON-01 compliance.** Any rephrasing MUST keep each bullet under 15 words.

## Maintenance notes

If the list of archetypes in Section 14.1.1 of the Debrief stakeholder specification ever expands (new archetypes added, existing ones renamed), this file MUST be updated to add the corresponding entries. Orphan archetypes — an `archetype` value in `debrief_state.json` that has no matching entry here — fall back to the `## custom` entry, but this should only happen in transition periods.

If new slide types are added to REQ-STYLE-10 step 2 (e.g., a fourth preview slide type beyond title / content-diagram / data-exhibit), this file's schema MUST be extended to include the additional fields. Current entries have 6 fields (`title`, `subtitle`, `author`, `institution`, `content_bullets`, `data_exhibit_caption`); any schema expansion requires updating all 8 archetype entries AND the variation catalog.
